INTERPRETATION:
Which fields are populated depends on the berekeningstype:
- NTA 8800 (labels issued after Dec 2021): ep1, ep2, aandeel_hernieuwbaar, warmtebehoefte, compactheid, gebruiksoppervlakte populated. energie_index = null. EMG forfaitair populated for utiliteitsbouw only (null for woningbouw). sbi_code = null. This rule concerns `berekeningstype`, `ep1_energiebehoefte_kwh_m2`, `ep2_fossiel_kwh_m2`, `aandeel_hernieuwbaar_pct`, `warmtebehoefte_kwh_m2`, `compactheid`, `gebruiksoppervlakte_thermische_zone_m2`, `energie_index`, `ep2_fossiel_emg_forfaitair_kwh_m2`, `aandeel_hernieuwbaar_emg_forfaitair_pct`, `gebouwklasse`, `sbi_code`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- NEN 7120 / ISSO 75.3 (commercial buildings, labels before Dec 2021): energie_index populated; ep1/ep2/warmtebehoefte = null. berekend_energieverbruik inflated (200–1200+ kWh/m²). EMG forfaitair = null. sbi_code = full-text sector description. This rule concerns `berekeningstype`, `energie_index`, `ep1_energiebehoefte_kwh_m2`, `ep2_fossiel_kwh_m2`, `warmtebehoefte_kwh_m2`, `berekend_energieverbruik_kwh_m2`, `ep2_fossiel_emg_forfaitair_kwh_m2`, `aandeel_hernieuwbaar_emg_forfaitair_pct`, `sbi_code`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- Nader Voorschrift (residential labels before 2021): energie_index populated. CRITICAL: berekend_energieverbruik and co2_emissie use DIFFERENT UNITS — values of 80,000–100,000 are MJ total building, NOT kWh/m². Do NOT benchmark. This rule concerns `berekeningstype`, `energie_index`, `berekend_energieverbruik_kwh_m2`, `co2_emissie_kg_m2`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- BENG eisen (eis_*): only for new-build BENG certification permits. Almost always null for existing buildings. This rule concerns `eis_energiebehoefte_kwh_m2`, `eis_primaire_fossiele_energie_kwh_m2`, `eis_aandeel_hernieuwbare_energie_pct`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- gebouwtype/gebouwsubtype: only populated for Woningbouw (residential). Null for all Utiliteitsbouw. This rule concerns `gebouwtype`, `gebouwsubtype`, `gebouwklasse`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- matchStatus 'exact': single VBO found, high confidence This rule concerns `matchStatus`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- matchStatus 'multiple_vbos': multiple verblijfsobjecten at this address. Profile shows the first match — use huisletter/toevoeging to target a specific unit. This rule concerns `matchStatus`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- matchStatus 'not_found': no BAG match — check postcode format (4 digits + 2 uppercase letters) and huisnummer This rule concerns `matchStatus`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- energielabel null: no registered label in EP-Online (common for older or unlabeled buildings) This rule concerns `energielabel`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- ep1_energiebehoefte_kwh_m2 (NTA 8800 only): Paris Proof 2040 targets — kantoor: 70 kWh/m², woningbouw: 100 kWh/m². No standardized target for onderwijs, gezondheidszorg, industrie. This rule concerns `ep1_energiebehoefte_kwh_m2`, `gebruiksdoel`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- CALCULATED vs MEASURED — ep1_energiebehoefte, ep2_fossiel and berekend_energieverbruik are all CALCULATED NTA 8800 figures, not meter readings: ep1 is net energy DEMAND, ep2 is PRIMARY FOSSIL energy, berekend is modelled total use. Paris Proof and other metered benchmarks are defined on MEASURED FINAL energy at the meter, and this server holds NO metered data, so none of these three can be ranked against such a target as though it were measured consumption — the unit (kWh/m²) matches and the quantity does not. Where a question asks how a building compares to a metered benchmark, say that the comparison cannot be made from this data and why, rather than producing a ratio. This rule concerns `ep1_energiebehoefte_kwh_m2`, `ep2_fossiel_kwh_m2`, `berekend_energieverbruik_kwh_m2`. History: Added 2026-09-21. Before it, the benchmark-trap eval question scored 0 of 60: runs ranked these calculated figures against the metered Paris Proof target as though they were measured use. With the line, 59 of 60. Q4 (2026-09-22) then tested the fact half and the instruction half separately; see evals/open-questions.md Q4.
- energie_index (pre-NTA 8800): the main performance metric for most existing buildings. EI < 1.2 = A or better; 1.4–1.8 = C; >2.7 = G. No Paris Proof kWh/m² equivalent. This rule concerns `energie_index`, `energielabel`. History: Present since the initial commit (2026-04-13). The reason for this wording was not recorded.
- gebruiksoppervlakte_thermische_zone_m2 (NTA 8800 only) vs oppervlakte_m2 (BAG): two different scopes, not two measurements of the same thing. BAG = gross floor area of the verblijfsobject; EP-Online = usable floor area of the thermal zone the label covers. The EP-Online figure is often the lower of the two, but when the label covers a whole pand and the VBO is one unit of it, it can be far higher (Gustav Mahlerlaan 10: 118,174 m² EP-Online vs 66,581 m² BAG). Use the EP-Online area as the denominator for every per-m² NTA value (EP-1, EP-2, warmtebehoefte, co2_emissie), and never assume a fixed ratio between the two. This rule concerns `gebruiksoppervlakte_thermische_zone_m2`, `oppervlakte_m2`, `ep1_energiebehoefte_kwh_m2`, `ep2_fossiel_kwh_m2`, `warmtebehoefte_kwh_m2`, `co2_emissie_kg_m2`. History: Rewritten 2026-09-20 (#33). The earlier wording said the EP-Online area runs '10-30% lower' than BAG. Gustav Mahlerlaan 10 is 77% higher (118,174 vs 66,581 m²), because the VBO is one unit of a pand the label covers whole. The same PR fixed the gas and CO2 alerts, which had multiplied per-m² NTA values by the BAG area.

// get_weather_context: INTERPRETATION block of the tool description
INTERPRETATION:
- isForecast per day = MEASURED (archive) vs FORECAST (predicted). Forecast days are fine for a planning outlook (icon + temperature) but are excluded from degree-days, gasNormalizationFactor and solar totals — those summary aggregates cover the measuredDays only. Never normalize energy against a forecast day. This rule concerns `isForecast`, `measuredDays`, `forecastDays`, `totalHDD`, `totalWeightedHDD`, `totalCDD`, `gasNormalizationFactor`, `solarRadiation`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
- weatherCode is the raw WMO code; prefer weatherLabel (Dutch, "Onbekend" if the code is missing) for display. This rule concerns `weatherCode`, `weatherLabel`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
- gasNormalizationFactor = 2800 / totalWeightedHDD. The Dutch long-term average year has ~2800 weighted HDD. A cold year (factor < 1.0) means raw energy use looks high — but that's expected. A warm year (factor > 1.0) means raw energy use looks low. Formula: normalizedHeatingEnergy = actualHeatingEnergy × gasNormalizationFactor. IMPORTANT: gasNormalizationFactor is only valid for full-year (Jan 1–Dec 31) queries. For partial-period year-over-year comparison, use the HDD ratio directly: normalizedEnergy = energy × (refPeriodHDD / thisPeriodHDD). This rule concerns `gasNormalizationFactor`, `totalWeightedHDD`, `referenceAnnualHDD`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
- GHI (global horizontal irradiance) in kWh/m² = Peak Sun Hours (PSH) for the period. Expected solar yield = totalGHI_kWhM2 × installedKwp × performanceRatio (0.75–0.85 for healthy panels). If actual production < 70% of expected yield → investigate: inverter issue, soiling, shading, curtailment. This rule concerns `solarRadiation`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
- Dutch weighted HDD seasonal factors: Nov–Feb ×1.1, Mar/Oct ×1.0, Apr–Sep ×0.8. These account for solar gain: in summer, the sun provides heat gain that partially offsets heating demand. This rule concerns `weightedHdd`, `weightedHDD`, `totalWeightedHDD`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
- select: when requested, records are projected to only the named fields. Unknown field names are ignored (with an alert naming them, valid fields listed). If none of the requested fields are valid, zero records are returned — select never silently falls back to full records. This rule concerns `records`, `recordCount`. History: Written with the tool on 2026-08-29 (#20). The reason for this wording was not recorded.
